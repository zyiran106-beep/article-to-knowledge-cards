# Make Knowledge Cards

## Overview

将一篇文章压缩成一组可独立复习的知识卡片：每张卡片只承载一个知识点，且每个字段都能回溯到原文。目标是便于回忆与自测，而不是复述文章结构或凑满数量。

## 输入边界

- 接受：用户直接粘贴的文章正文；本地 Markdown（`.md`）与纯文本（`.txt`）文件。
- 读取本地文件时，先确认扩展名；其他格式按「不支持」处理。
- 明确不支持：网页抓取与 URL 读取、PDF、Anki 导出或导入、图形界面操作。
- 遇到不支持的输入时，停止处理，用固定句式回应：`不支持 {输入类型}，请粘贴文章正文或提供 .md/.txt 文件。` 不要尝试用其他工具绕过。

## Workflow

### Step 1：获取原文

- 用户粘贴正文时，直接以粘贴内容为原文。
- 用户提供本地文件路径时，读取文件内容；只接受 `.md`/`.txt`。
- 确认原文非空；若为空或只有标题、目录、链接列表等无实质内容，按信息不足处理（见 Step 3）。

### Step 2：提取知识点候选

通读全文，在内部列出候选知识点（不输出候选列表）。一个知识点指一条可被独立回忆的事实、概念、机制、方法、结论、数据或反直觉发现。

判定「重要」的标准，满足任一即可入选：

- 直接回答文章的核心问题或支撑文章主旨。
- 是理解全文所必需的关键概念、因果机制或方法步骤。
- 是关键数据、边界条件或结论，删掉会导致读者误解文章。
- 是反常识、易混淆或容易被忽略的发现。

排除以下内容：

- 背景铺垫、写作动机、过渡句、修辞与修饰性细节。
- 同一观点的重复表述、举例堆叠。
- 无法在原文中找到依据的引申或常识补全。判定标准：每个实质信息必须能在原文中找到对应原句或直接改写；若需要原文之外的常识才能推出，则删除。

### Step 3：去重、筛选与定数量

- 合并：同一知识点在不同段落的重复表述合并为一张卡片。
- 拆分：能用「因为 / 所以 / 随之 / 从而」连成一条因果链的连续环节算一个知识点，不拆；必须用「另外 / 同时 / 此外」连接、且互为独立结论的，拆成两张。
- 概括与机制：若某句只是对后文机制的概括（例如「某过程起主动作用」），不单独成卡，并入机制卡的简明解释。原文以「也就是说」「换言之」引出的句子视为重述，不单独成卡；若该句给出新的行动建议，可放进上一张卡片的 `例子：` 字段。
- 排序：按对理解全文的重要性从高到低排列。默认优先级为：文章主旨结论 → 关键机制与方法步骤 → 主要局限与误差来源 → 关键参数与数据 → 验证方式 → 定义与背景。仅当某条定义被全文反复使用、且删去后其余卡片不可读时，才可提到首位；否则并入相关卡片的解释。
- 超过 8 个知识点时，先合并同主题条目，再按上述优先级取前 8 张；被舍弃的次要信息不输出，不另设「其他」卡片，不为了保留次要信息而牺牲关键机制或主要局限。
- 少于 5 个知识点时，按实际数量输出，并在末尾按固定句式说明；不要编造内容，也不要把一句话拆成多张卡来凑数。

### Step 4：写卡片

严格按照固定顺序写四个字段，不得增减字段、不得改变顺序：

1. **标题**：简短、具体，只指向一个知识点；避免「背景介绍」「总结」这类空泛标题。
2. **核心知识**：一句话陈述结论或事实，必须原文明确写出或由原文严格逻辑蕴含。
3. **简明解释**：用 1 至 4 句（优先 2 至 3 句）说明「是什么 / 为什么 / 如何成立」，每一个实质信息仍需来自原文。原文只给出一句事实时，写 1 句即可，允许直接引用原文原句，不要求与核心知识措辞不同，这不算凑句；禁止写出第 2、3 句同义重复，或添加原文没有的修饰细节。直接陈述知识内容，避免「原文指出」「原文强调」这类元叙述。
4. **例子或自测问题**：二选一，必须带前缀 `例子：` 或 `自测：`。
   - `例子：` 仅使用原文中用于说明该知识点的具体案例、数据、对象或场景，并保留原文的条件与数值。只是重述核心知识中的条件或结论不算例子，应改写为 `自测：`。
   - `自测：` 写一道以「？」结尾的问题，答案必须能在本卡片的「核心知识」或「简明解释」中直接找到；不要写出答案。
   - 原文没有合适的具体例子时一律写自测问题，不写入新事实。

写作约束：

- 一张卡片只讲一个知识点，不夹带第二个结论。
- 不引入原文之外的知识、数据、术语或评价，即使这些内容是公认正确的。
- 不把推测写成事实；原文表述不确定时，在卡片中保留同样的确定性程度（例如「原文认为」「在某些条件下」）。
- 卡片之间相互独立：单张卡片脱离上下文也应可读，不写「见上文」「见卡片 N」等交叉引用。

### Step 5：输出前自检

逐项核对，发现问题就回到 Step 3 或 Step 4 修正后再输出：

- 每张卡片四个字段齐全、顺序一致。
- 每张卡片只有一个知识点，卡片之间没有重复内容。
- 每个实质信息都能在原文中找到依据；无法回溯的已删除。
- 「简明解释」没有为凑句数产生的重复、新增细节或元叙述。
- 「例子或自测问题」带正确前缀；自测问题以问号结尾且答案在卡片内。
- 卡片数量为 5 至 8；少于 5 时已按固定句式说明原因。
- 未对不支持的输入类型做处理。

## 输出格式

按以下格式输出卡片，卡片之间空一行；不要在卡片之前加长篇说明。

```
### 卡片 1：{标题}

- **核心知识**：{一句话结论}
- **简明解释**：{1 至 4 句解释}
- **例子或自测问题**：{例子：原文案例；或 自测：以问号结尾的问题}
```

末尾追加一行统计：`本次生成 N 张卡片。` 若 N 小于 5，在同一行补上原因：`原文可提炼的独立知识点不足 5 个，未补充外部内容。`

## 常见错误与修正

| 错误 | 修正方式 |
| --- | --- |
| 用外部常识补全原文没写的机制 | 删除该信息，只保留原文可依据的部分 |
| 把背景、修辞或过渡句当成知识点 | 回到 Step 2 的排除清单剔除 |
| 为凑满 8 张把一条结论拆成多张 | 合并为一张，或按实际数量输出 |
| 自测问题的答案在卡片内找不到 | 重写问题，使答案落在核心知识或简明解释中 |
| 一张卡片出现两个并列且互不依赖的结论 | 拆成两张，各自只讲一个知识点 |
| 简明解释只有一句原文却硬凑成 3 句 | 保留 1 句原文原句即可，删除重复表述与新增细节 |
| 「例子或自测问题」写成无前缀的陈述句 | 改为 `例子：...` 或 `自测：...？` |
| 「例子」只是把核心知识换个说法 | 改写成带原文具体对象的例子，否则改为 `自测：` |
| 超过 8 个知识点时随意丢弃关键局限 | 按 Step 3 的优先级排序后再取舍 |
| 统计行同时写两个 N | 只写生成卡片的数量 |
| 收到 PDF、网址或非文本文件仍继续处理 | 停止并按固定句式说明不支持 |
